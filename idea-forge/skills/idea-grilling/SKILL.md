# 想法拷问协议（grilling）

目的：在动手产出之前，把想法里所有被默默假设掉的东西逼到台面上。

访谈结束的标准**不是**「问够了」，而是**前沿为空，且用户确认理解一致**。

## 何时用 / 何时不要用

**用**：想法还有关键决策悬空；用户自己说不清楚；方案看起来合理但没人检查过它的前提；投入较大、难以回头。

**不要用**：

- 任务小、便宜、随时可撤——直接做，别搞仪式。
- 用户只要一个事实或一个执行步骤，没有决策悬空。
- 用户已经明确拍板，你要做的只是落实——此时提问是在拖进度。
- 你只是想「表现得严谨」而列问题——这属于框架表演，停下。

**停止信号**（出现就该收尾，而不是硬撑轮次）：连续一轮只能问出既有问题的措辞变体；或者再问下去只是把已经定过的东西重新问一遍。

## 三个核心概念

- **决策树**：把想法建成一棵树。每个决策下面挂着由它衍生的决策。根通常是「这个想法到底要解决什么问题」。
- **前沿（frontier）**：所有前置条件都已确定的决策，也就是此刻能诚实提问、不需要猜答案的问题集合。
- **轮次（round）**：一次问完整条前沿，一次收完这一整轮的答案。

## 轮次规则

1. 一轮只包含**互不依赖**的问题。若问题 B 的答案取决于问题 A，而 A 本轮尚未有答案，则 B 属于**下一轮**。
2. 一轮问完就停，等用户答完再算下一轮。不要边问边追问、不要把下一轮提前塞进来。
3. 每轮结束后重算前沿：已定的决策把前沿向外推，解锁新的问题。
4. 13 个问题通常落成 3 轮，而不是 13 轮。**问题要多，轮次要少。**
5. 需要查证才能问的问题，不要拿去问用户；挂起该分支去查（见下），只推迟依赖它的问题。

## 问题格式

每个问题固定三段，让用户能直接按编号回答（「1 同意，2 选第二个，3 不，因为…」）：

```
❓ **Q1 —— <问题标题>**：<问题正文，可以多段，可含选项>

➡️ <你的推荐答案>
```

问题之间用 `---` 分隔。

推荐答案必须给出。它有两个作用：把用户的操作成本压到「同意/不同意」，以及把你的推理摆出来接受检查。若你的推荐恰好与问题字面表述相反，明确写「按字面回答是"否"，因为…」，不要让用户猜。

## 事实归你，决策归用户

- **事实**：环境、文件、目录、公开数据、竞品信息、行情数字——全部是你的活。自己用文件/联网工具查，或派子代理去查。**绝不问用户「你说的 X 是什么情况」这类自己能查到的问题。**
- **决策**：目标、约束、取舍、口味、优先级——是用户的活。每个决策都要摆到用户面前并**等待**答复。
- 自问自答用户的决策不是「灵活执行」，而是**跑偏**。**访谈中替用户拍板，等于这次访谈作废。**

## 不要阻塞在一件事上

后台还在跑的研究不算「已定」，所以**只有依赖它的问题**推迟到研究回来；本轮其余问题照常问。不要为了让研究先完成而空转整轮。

## 结束与确认闸门

- 结束条件是**前沿为空**：每根分支都走过，没有东西被默默假设。
- 前沿为空**不等于**可以动手。必须显式请用户确认「双方理解一致」，得到确认后才进入落实阶段。
- 用户没确认之前：不要写成品文档、不要给「最终方案」、不要开始执行。

## 反模式（出现任意一条即说明跑偏）

- **问了两个问题就急着给方案**——把「访谈直到理解一致」塌缩成「问两句 + 一份大纲」，是最常见的失败。
- **替用户回答自己的问题**。
- **一轮里塞进互相依赖的问题**——用户无法按序作答。
- **问用户本该自己查的事实**。
- **没有问题推荐答案**——把决策成本全部推回给用户。

## 诚实边界

前沿是你的判断，不是计算出的图。你可能会把两个问题放进同一轮，事后才发现其中一个的答案本该改变另一个。没有机制能防住这件事，只能：一旦发现，明确说出「这轮 Q2 的前提被 Q3 推翻了」，并在下一轮重开那根分支。

## 自查清单（跑得对不对）

- 一轮到货时是编号列表，每题带一条独立 `➡️` 推荐行，用户能按编号整轮回答。
- 同轮内没有任何问题需要先得到同轮另一问题的答案。
- 后一轮问的，是前一轮根本问不出来的东西。
- 事实是查来的，不是问来的。
- 后台查证没有拖住整轮。
- 结束后停下来请用户确认，而不是直接开工。
- 问题数高、轮次数低。
