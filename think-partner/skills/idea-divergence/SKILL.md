# Diverge, then converge

An idea that will not refine further is usually not "not deep enough" — its **option space is too narrow**.

Open the space first, then close it. **Never do both in the same pass** — generating while judging is the number one cause of creative block.

## When to use / when not to

**Use** when: only one path is visible; you must choose between options; you are stuck on whether to do it at all; you are out of ideas; you must prioritise a long list.

**Do not use** when: the options are already clear and only execution remains; the task is routine with no real tradeoff; the user is picking between two near-identical options and you merely want to look thorough.

**Stop signals**: new output is only a rewording of existing options; or every new angle lands in a perspective already covered — the space is open enough, converge.

## 0. Classify reversibility first (the first cut on any decision)

Before comparing options, label each one:

- **Two-way door** — undo is cheap. Stop over-analysing. Try it fast and buy information at the smallest possible cost.
- **One-way door** — you cannot go back, or the cost is high. Worth the full treatment: pre-mortem, opportunity cost, second-order effects.

Most "I can't decide" is a two-way door being analysed as if it were a one-way door. Once classified, the half that should be fast becomes fast immediately.

## 1. Diverge: quantity first, quality later

Rules:

1. **Volume first** — get to 8–12 options before judging any.
2. **Defer judgement** — "that won't work" is banned during generation.
3. **Yes-and** — build on an existing idea instead of replacing it.
4. **At least two wild ideas** — they are often the only route to the practical answer.
5. **Constraints raise creativity** — no boundary means no direction; do not start from "anything goes".
6. **Mix perspectives** — different users, roles and time horizons.

Techniques (pick 1–3, not all of them):

- **SCAMPER** — substitute / combine / adapt / modify-magnify / put to another use / eliminate / reverse-rearrange.
- **Reverse brainstorming** — first ask "how could we guarantee this fails?", list the failure modes, then flip each one into a success strategy. Especially good at surfacing hidden risk.
- **Constraint removal** — what if the budget were unlimited? What if time were not a factor? What if you could pick any technology? What if there were no legacy? Then ask which of those scale back to reality.
- **Hybrid combination** — take the strongest part of A, B and C and build 2–3 hybrids instead of choosing one.
- **Perspective rotation (Six Thinking Hats)** — walk the facts / intuition / risk / benefit / creativity / process hats in turn.

## 2. Converge: fixed criteria, not vibes

1. Set the criteria first — usually four are enough: **feasibility, impact, cost, risk**, each 1–5.
2. Build a comparison matrix, score each cell, and give a total and a recommendation.
3. Every score needs a **reason**. "Feels like a 4" is not a reason.
4. Say **why the rejected options were rejected**. A recommendation without rejections is not an evaluation.

## 3. Four fixed interrogations (mandatory at the converge stage)

- **Pre-mortem** — assume this has already failed completely and work backwards: what went wrong? Which warnings were ignored? Which assumption proved false? What can be done now to prevent it?
- **Second-order effects** — what happens after the first layer? Who changes their behaviour because of it? What unintended consequences appear? What feedback loops form?
- **Opportunity cost** — choosing this means not doing what? Which resources are locked up? Which options are foreclosed? How expensive is reversing?
- **Inversion / steel-manning** — argue the opposing case as strongly as it can be argued, then respond to *that*. No straw men.

## 4. Always close with

- **What evidence would change your mind?** If there is no answer, this is a position, not a judgement.
- The conclusion must land on exactly one of **proceed / modify / abandon**, with the reasoning and the next smallest validating action.
